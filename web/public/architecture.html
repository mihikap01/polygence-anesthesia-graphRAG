Polygence pharmacogenomic graph-RAG · reproduction guide

How to reproduce every result in this project, step by step

Author: Mihika Pall · Polygence (2026). Run-along instructions for someone reading the codebase for the first time — every command, every expected output, every cost and time estimate.

Live demo → Eval report → GitHub repo →

If you run every step below in order, by the end you will have:

(1) The knowledge graph built from PharmGKB (3,213 nodes, 8,024 edges).

(2) The interactive web app running locally at http://localhost:3000, with the Cytoscape graph canvas and the Explain / Chat panels powered by your local Claude CLI.

(3) The full evaluation rerun from scratch: 187 held-out questions, three retrieval conditions, four metric families, the same eval/report.html that's published at /eval-report.

Total wall time: ~5 hours (most of it the LLM generation in step 8). Total cost: ~$45 in Claude API spend. Skip the eval if you only want the demo: ~5 minutes.

Step 3 — Build the PharmGKB knowledge graph

3

Turn the raw TSVs into JSON artifacts

~3 seconds $0

A single Python script (no pip dependencies, just stdlib) parses six PharmGKB TSVs and produces three JSON files under data/.

python3 preprocess/build_graph.py
What this does
  • Parses clinicalVariants.tsv (5,188 rows) as the backbone
  • Harvests PMIDs from relationships.tsv (127k rows)
  • Drops not associated / ambiguous rows (focuses on the signal graph)
  • Collapses rsIDs into per-gene variant clusters
  • Injects curated drug-class nodes (Volatile Anesthetics, NMBs, etc.)
  • Tags 1A/1B Toxicity edges as CRITICAL (highlighted red in the UI)
Expected output
Loading reference metadata...
  genes=25041  drugs=11535  phenotypes=1615
Building simplified graph...
  nodes=3213  edges=8024
Building anesthesia seed view...
  seed nodes=36  seed edges=62
Writing JSON artifacts to data/...
Done.
Verify: ls data/ should show graph.json (~2 MB), seed_anesthesia.json (~28 KB), search_index.json (~302 KB).

Step 4 — Run the web app locally

4

Start the Next.js dev server

~5 sec to start, stays open $0 (uses your Claude Code auth)

The dev script auto-installs deps and builds the graph if missing.

scripts/dev.sh
# → opens http://localhost:3000
Try in the browser
  1. The page loads with the anesthesia / malignant-hyperthermia subgraph (36 nodes) — sevoflurane, succinylcholine, RYR1 cluster, CACNA1S, etc.
  2. Click any node (try RYR1) → the right Explain panel runs /api/explain, which fires retrieveForQuestion() for its 2-hop neighborhood and spawns claude -p in the background. Answer arrives in ~3-8 seconds.
  3. Switch to the Chat tab and ask: "Why is sevoflurane risky for malignant hyperthermia?". Watch the retrieval strip at the top of the answer — it shows the linked entities (sevoflurane, MH, isoflurane noise), the shortest paths surfaced, and the subgraph size in nodes/edges.
  4. Expand "Context sent to model" at the bottom of any answer — this shows the exact system prompt, user prompt, retrieved subgraph, and token estimate. Every retrieval step is observable.
Verify: curl http://localhost:3000/api/graph?view=seed returns a JSON graph with 36 nodes.

Step 7 — Reproduce the evaluation: generation

7

Generate the 561 answers (3 arms × 187 questions)

~3-4 hours ~$25 resumable

For each question, runs three arms in turn via claude -p --model sonnet:

  • A0 — no retrieved context (the LLM alone)
  • A1 — plain-text RAG (top-8 chunks from step 6c, RRF-fused)
  • A3 — subgraph RAG (entity-link → 1-hop neighborhood → shortest paths via eval/retrieve_py.py)
python3 eval/run.py --model sonnet
Progress output
questions: 187, already done: 0, arms: ['A0', 'A1', 'A2', 'A3']
model: sonnet
A3: loaded held-out graph (3203 nodes)
[5/748]  S1-002 A0   11.8s  $0.0432  ✓ 1389 chars  · eta 31.0min  · $0.04 total
[6/748]  S1-002 A1   11.7s  $0.0298  ✓ 1083 chars  · eta 63.9min  · $0.07 total
...

Resumable: if the process exits or hits a rate limit, just re-run the same command — already-completed (question, arm) pairs are skipped.

Verify: wc -l eval/answers.jsonl → 561+ records (resume retries may add a few duplicates that the grader dedupes). Run python3 -c "import json; d={(json.loads(l)['question_id'], json.loads(l)['arm']) for l in open('eval/answers.jsonl') if not json.loads(l).get('error')}; print(len(d))" to count unique successful (qid, arm) pairs — should be ≥ 560.

Step 8 — Reproduce the evaluation: scoring (four metric families)

8a

Rule-based metrics (deterministic Python, no LLM)

~3 sec $0

PMID-exists, entity precision/recall, evidence-level exact-match, refusal correctness — all defined symmetrically across arms.

python3 eval/grade.py
loading corpus PMID set...
  9,128 unique PMIDs in relationships.tsv
grading 748 unique (question, arm) pairs (from 811 raw rows)...
wrote 748 scores to eval/scores.jsonl
8b

Blinded pairwise preference (THE PRIMARY TEST)

~20 min @ 6 workers ~$7

For each question, Claude Haiku judges A3 vs A1 (primary) and A3 vs A0 (secondary), blinded, with order randomised. Sign-test p-value reported.

python3 eval/judge.py --workers 6 --model haiku
judging: 374 comparisons total · 0 done · 374 to do
model=haiku · workers=6
[1/374]  S1-001 A3_vs_A1  12.4s  → A1  · eta 11.4m  · $0.02
...
done. judgments in eval/judgments.jsonl · $7.13 · 18.0min
8c

Anchored 1–5 rubric ratings

~30 min @ 8 workers ~$9

Per answer, Haiku rates Faithfulness / Completeness / Clinical-soundness 1–5 against ground truth.

python3 eval/judge_rubric.py --workers 8 --model haiku
8d

Merged-claim hallucination rate

~40 min @ 4 workers ~$3

Per question, the judge extracts the union of atomic factual claims across all four answers and labels each as supported / unsupported / unverifiable. Same denominator across arms.

python3 eval/segment.py --workers 4 --model haiku

Note: this script is known to hit Claude CLI hangs on some questions (the 120s timeout doesn't always fire cleanly). The original run achieved 57/187 coverage before being stopped. Treat the rates as directional, not definitive.

Recommended next steps

If you want to make the eval stronger (per the report's "Conclusions" section §7):

  1. Hold out relationships.tsv rows in parallel with clinicalVariants.tsv to close the partial-leakage confound (see report §6.2).
  2. Inline PMIDs into A3's structured context (~10-line change in eval/retrieve_py.py); re-run the citation stratum only.
  3. Re-judge with a cross-family judge (Gemini instead of Haiku) and compare against the within-Claude result.
  4. Add a hybrid arm (A4 = A3's subgraph + A1's top-3 chunks) and re-run pairwise.
  5. For more ambitious work: implement a Microsoft-style GraphRAG arm with Leiden communities + LLM-generated community summaries.
