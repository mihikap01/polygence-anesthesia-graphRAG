GraphRAG evaluation — results

Cross-arm comparison on a held-out PharmGKB question set. Generator: Claude Sonnet 4. Judge: Claude Haiku 4.5 (cross-size, within-Claude). See eval/preregistration.md for design.

Key findings

H1 (primary): NOT SUPPORTED GraphRAG (A3) vs. strong naïve RAG (A1): 48.9% A3-preferred (91–95, sign-test p=0.826). This is a statistical tie — the graph layer did not beat strong hybrid retrieval on this question set. The pre-registered bar was >55% with p<0.05.
  • H2 (multi-hop): not supported. On S3 (multi-hop), A3 was preferred only 42.5% of the time — it lost to A1. This matches the hostile reviewer's prior: PharmGKB rows are already denormalised, so a strong retriever recovers multi-hop facts without needing graph traversal.
  • H3 (no regression): mild regression. On S1 (well-known facts) A3 was preferred only 35.0% vs A1 — the extra graph context reads as noise on trivially-known questions.
  • A3's one genuine win: out-of-distribution refusal (S7, 60.0%). When a drug isn't in the graph, A3 cleanly refuses; A1's retrieval always returns something, tempting it to answer. This is the clearest evidence that graph structure helps — knowing what's absent.
  • A3's apparent S4 win (96.0%) is a confound, not a win. The held-out split removed clinicalVariants rows but not relationships.tsv rows, so A1 could still retrieve the (correct) PMIDs while A3's graph genuinely lost them. The judge then preferred A3's refusal over A1's correct citation — rewarding caution over verifiable grounding.
  • The meta-finding — preference ≠ correctness. A0 (no context) "won" the preference test (27.8% A3-preferred, p=0.0000 — i.e. A0 strongly favoured), yet A0's cited PMIDs were real only 31.7% of the time vs. 66.7% for A3. The LLM judge is fooled by fluent, confident prose and cannot detect fabricated citations. This is precisely why the design pairs subjective preference with deterministic rule-based metrics.
Bottom line On this PharmGKB-derived benchmark, with Claude Sonnet as the generator, the GraphRAG layer did not demonstrate an advantage over strong hybrid retrieval, and both retrieval arms were dispreferred by the LLM judge relative to the model's own parametric answers — which are themselves unreliable (high PMID fabrication). The honest conclusion: for this domain and model, the value of the graph is concentrated in knowing what it does NOT contain (refusal), not in multi-hop reasoning. See the threats/deviations section for why these numbers should be read with caution.
Rubric + hallucination metrics corroborate The two additional judge passes (per-answer rubric ratings and merged-claim segmentation) tell the same story from different angles:
  • Rubric Faithfulness (1–5): A0 3.49, A1 3.43, A3 3.07. The Haiku judge rates A0 and A1 higher on faithfulness than A3 — again rewarding confident prose over careful graph-grounded answers.
  • Merged-claim support rate (same denominator across arms): A0 74.1%, A1 69.1%, A3 66.6%, A2 55.1%. A0's substantive claims are largely correct from parametric memory — even though its specific PMIDs are fabricated 68% of the time. The system "knows the facts" but "lies about the citations." A3 sits in the middle: fewer fabricated citations than A0 (33% vs 68%), but the judge can't see that.
Two completely independent metric families (preference, rule-based, rubric, segmentation) all point to the same conclusion: GraphRAG is more grounded but the judges systematically prefer A0's fluent parametric answers. The eval works as a mirror on what LLM-as-judge can and cannot detect.

Deviations & threats (read the numbers with these in mind)

  • Generator was Sonnet, not Opus. Pre-registration named Opus; we used Sonnet for cost/throughput (~10× cheaper). A stronger generator might change A0's parametric quality.
  • Judge was Claude Haiku judging Claude Sonnet (within-family). Self-preference bias is only partially mitigated; cross-family (Gemini) judging would be stronger.
  • relationships.tsv leakage. Only clinicalVariants rows were held out; relationships.tsv (which restates many associations + PMIDs) was not. This gave A1 access to nominally held-out facts — the S4 result is confounded by this.
  • A1 steelman omitted the BGE reranker (BM25 + dense + RRF only) to keep the laptop install light. A reranker would likely make A1 even stronger, not weaker — so A3's non-advantage is, if anything, understated.
  • Refusal/negative metrics are keyword-heuristic and noisy; treat S6/S7 rule-based numbers as directional.
  • Single model, single judge, n≈25–40 per stratum. Per-stratum numbers are descriptive, not inferential. Only the n=187 pairwise test is adequately powered.
