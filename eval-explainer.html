Eval design · v2 · post stress-test

How we'll prove GraphRAG actually helps.

An honest, falsifiable test of whether the graph layer adds value beyond "just giving the LLM some context." Designed so a clean win means something — and a tie or loss is publishable, too.

1 · The claim

What are we trying to prove?

The GraphRAG system makes a specific claim: that combining a curated PharmGKB knowledge graph with retrieval-augmented reasoning produces answers that are more faithful, more specific, and less hallucinated than a frontier LLM produces alone — and that the benefit comes from graph structure, not just "having any context at all."

Why this is hard A frontier model has likely seen PharmGKB during training, so "no context" isn't a blank slate. Naïve text-search RAG would give it relevant snippets without any graph. And if the test questions come from the same data the graph is built on, GraphRAG wins trivially. The whole design is about ruling out those cheap explanations.
2 · The setup

Four versions of the same model, only the context differs

We ask the same frontier model (Claude Opus 4.7) the same question, four different times — varying only what it sees alongside the question. Then we compare which version answered best.

A0 · No context

Question only

The LLM with nothing else. Tests: how much does it already know from training?

A1 · Naïve RAG (steelman)

Strong text-search retrieval

Hybrid BM25 + dense embeddings, reranker, query rewriting. Tests: did retrieval help, irrespective of structure?

A2 · Full context

Whole subgraph as text

Dumps the relevant region of the graph as plain text. Tests: did smart retrieval matter, or is a big context window enough?

A3 · GraphRAG

The system under test

Entity linking → 1-hop neighborhoods → shortest paths → structured prompt. This is what we built.

Why A1 is the most important comparison Beating A0 is easy — of course context helps. Beating A1 means the graph structure did something that plain text retrieval couldn't. If A3 ties A1, GraphRAG didn't earn its complexity. That would be a real finding, not a failure.
3 · The questions

Where do the 200 test questions come from?

1
Start with PharmGKB's high-quality rows From clinicalVariants.tsv, take the ~400 rows with strong evidence (levels 1A/1B/2A/2B).
↓
2
Hide 30% of those rows Randomly hold out ~120 rows. Rebuild the graph without them. The naïve-RAG arm also has them removed from its index. Now nobody has memorized them.
↓
3
Auto-generate questions from the hidden rows 200 questions across 8 question-types (strata), each with a "gold" answer recorded — expected gene/drug, evidence level, valid PMIDs, and a "should-refuse" flag.
↓
4
Human spot-check the first 30 Toss any questions that are unclear or have no clean gold answer.
The trick The facts are real PharmGKB knowledge, but the exact rows are unseen by every arm. GraphRAG can still answer correctly — but only by reasoning over neighboring rows, not by memorization. Same for the naïve-RAG arm. That makes the comparison fair.

5 · The grading

Two passes: deterministic + Claude-Haiku judge

Each of the 800 answers (200 questions × 4 arms) gets scored two different ways. Arm labels are stripped before grading — graders don't know which version produced which answer.

Pass 1 — Rule-based metrics (Python, deterministic)

Checks verifiable facts. Same definition across all 4 arms — no arm gets free points or is penalized by construction.

  • PMID exists — does each cited paper ID actually exist in PubMed?
  • PMID correctly attributed — does the cited paper actually support that specific claim?
  • Entity precision / recall — did it name the right genes, drugs, phenotypes?
  • Evidence-level exact match — does claimed "1A" match gold "1A"?
  • Refusal correctness — did it refuse when the gold says "no association"?
Pass 2 — Claude Haiku 4.5 as judge (semantic, anchored rubric)

The generation model is Claude Opus 4.7; the judge is Claude Haiku 4.5. Different model sizes → different parameters → reduced (not eliminated) self-preference bias. Also human-spot-checked.

  • Faithfulness 1–5 — are claims supported by ground truth?
  • Completeness 1–5 — does it cover the key relationships?
  • Clinical soundness 1–5 — would a pharmacist call it misleading?
  • Pairwise preference — judge picks A or B blinded (this is the headline result, see next section).
6 · The headline result

One adequately-powered test: pairwise preference at n=200

For each of the 200 questions, the Haiku judge sees A3's answer side-by-side with A1's answer (blinded, randomly ordered) and picks which one better answers the question.

Sign test: at n=200, we can detect a 55%+ preference rate with >0.95 power at α=0.05. That means if A3 wins 110+ of the 200 non-tie comparisons, we have strong evidence that GraphRAG beats strong naïve RAG.

Why this one test, and not per-stratum With only 25–40 questions per stratum, statistical power is too low to make per-stratum claims rigorously (you'd need ~170 per stratum for the effects we care about). The per-stratum tables are still reported — they show where A3 wins or loses — but they're descriptive, not inferential. The pairwise test is the one we'd stake the headline on.
7 · The hypotheses

What "GraphRAG won" actually means, pre-declared

Three falsifiable hypotheses, committed to a file before any answers are generated. This prevents moving the goalposts after the fact.

H1 · Primary
A3 beats A1 on blinded pairwise preference, >55% of the time
Tested with: sign test on 200 pairwise comparisons. Decisive.
H2 · Multi-hop
On S3 (multi-hop questions), A3 entity recall + PMID precision both exceed A1 by ≥10 percentage points
Tested with: per-stratum rule-based metrics. Descriptive — explains where the H1 win comes from.
H3 · No regression
On S1 (easy / well-known facts), A3 is within 5pp of A0 — adding graph context doesn't hurt easy questions
Tested with: descriptive equivalence check on S1.
8 · Honest threats to validity

What could go wrong (acknowledged, not hidden)

Every eval has weaknesses. Listing them transparently makes the writeup stronger, not weaker. A mentor will notice these anyway — better to surface them ourselves.

Med
Training contamination — PharmGKB is public; the LLM may have seen it. Mitigation: held-out split + 15 fresh-phrasing questions.
High
A1 being a strawman — A weak naïve-RAG makes A3 look better than it is. Mitigation: A1's exact config (embedder, reranker, K, query rewriting) is pre-registered. If we can't stand up the steelman, the eval pauses.
Med
Judge self-preference (Claude judging Claude) — Even with Opus generating and Haiku judging, both are Claude. Cross-family judging (Gemini) would be stronger. Mitigation: lean on rule-based metrics (judge-independent); pairwise preference; human spot-check 20 ratings.
Med
Blinding-via-style — A3's structured prose is identifiable even with labels stripped. Mitigation: prose normalization before judging.
Low
Held-out rows ≠ held-out facts — Other TSVs may redundantly contain the same association. Both A1 and A3 get to use those rows, so the asymmetry is small.
Med
Single model — Results may not generalize to GPT or Gemini. Stated clearly; replicate on a second model as future work.
9 · Sanity checks before we run anything

Five gates before generating 800 answers

If any of these fail, the eval pauses and we fix it first — not after burning compute.

1
Question quality ≥85% Hand-rate 30 auto-generated questions on 0/1 (usable). If fewer than 85% are good, fix the templates.
2
Gold-answer verification Manually verify the same 30 against the held-out PharmGKB row — catches template bugs.
3
A1 sanity Run the naïve-RAG arm on 5 questions; confirm it actually retrieves reasonable chunks. A broken steelman invalidates the comparison.
4
Judge calibration Haiku rates 20 answers; you rate the same 20; correlation ≥ 0.7 required.
5
Pre-registration Commit metric definitions, A1 config, sample sizes, and decision rules to a file before generating answers. Frozen.
10 · What success looks like

The two outcomes we'd be happy with

A mixed result with a clear story is a better outcome than a clean win.

The hostile reviewer's prior is that A3 wins H1 with the win concentrated in multi-hop reasoning (S3), negative controls (S6), and out-of-distribution refusal (S7); ties A0 on easy questions (S1); and shows a characterizable set of remaining failure modes.

That's the version that demonstrates understanding — where the graph helps, where it doesn't, and why. A clean across-the-board win that doesn't survive scrutiny is a worse result, not a better one.
